# Kernel v19 扩大确认（采用决定轮）预登记方案 v2（设计稿，2026-09-28，待批准）

状态：设计稿，不授权冻结或执行，暂不改任何代码与 prompt。上游证据：
9-28 确认性测量 24 对通过预登记筛选（`2026-09-28-v35-v38-confirmatory-result.md`，
commit `cd00a1d`）；owner 排序裁定：本轮扩大确认 → 规划器有界真实测量 → T14。
本轮的问题只有一个：**是否在本设计范围内建议采用 v19**。24 对结果支持继续验证，
不足以宣称泛化；本轮加机制种类而不重复旧场景次数。质量判据失败后不为
改判追加样本；执行或完整性失败只报不可判。

## 1. 场景与分组（均取自标准 106 格；两个锚点是已测格）

依据 `p1-formal-v38.json`（与 v35–v38 同构）的 DIAGNOSTIC_KERNEL 排程与
scenario_catalog 角色分层（variant_role 是产品既有分类，非本轮新造）：

| 组 | 场景 | catalog 角色 | 机制 | 进入理由 |
| --- | --- | --- | --- | --- |
| 目标（列级可确认） | schema_type_change_order_customer_a | TEST_CONFIRMABLE | 列类型变更 | 同关系 schema 属必需证据；但合同不要求 profile，v19 的“接受 profile 后核对 schema”前提未必出现，单列该族结果 |
| 目标 | required_null_order_customer_a | TEST_CONFIRMABLE | 必填列空值 | 同关系 profile 与 schema 均属必需证据，更直接检验 v19 的条件式核对；单列该族结果 |
| 不足对照 | schema_type_change_order_customer_b | TEST_INSUFFICIENT | 列类型变更（证据不足变体） | v19 不得把"应声明不足"翻成错误确认 |
| 不足对照 | required_null_order_customer_b | TEST_INSUFFICIENT | 必填空值（不足变体） | 同上 |
| 不足对照 | silent_payment_drop_partition_b | TEST_INSUFFICIENT | 分区行丢失（不足变体） | 行级机制 + 不足角色双重对照 |
| 无事件对照 | order_volume_pattern_a | NO_INCIDENT_CONTROL | 无事件（健康） | schema 采集不得制造假事件，也不得因采 schema 耗尽预算把健康格跑败 |
| 锚点（仅描述，不进晋级） | duplicate_payment_coupon_a r1、orphan_payment_coupon_a r1 | TEST_CONFIRMABLE | 上轮目标机制 | 与 9-28 早块的相同 selector 格并排描述；单次差异不能归因于时间漂移 |

- 目标 12 对（stc_a、rn_a 各 r1–r3，早晚块各一次）；不足对照 9 对（stc_b、

- 本轮不触碰清单构成。rename、schema_type_change_payment_amount、T13 raw 级

  required_null_payment_id 均不在 106 格排程内，纳入需变更 formal_scenario_ids

## 2. 身份与分块（4 新身份，BAAB，13+13）

- 执行序 **B1(v39) → A1(v40) → A2(v41) → B2(v42)**；A=旧 v18 对照，
  B=v19 候选。每臂占一个早块一个晚块（块序平衡，不宣称消除时间混杂）。
- 双谱系配方与 v35–v38 逐字相同（冻结报告 `2026-09-28-v35-v38-freeze.md` §1）：
  B 谱系在 main（v19 时代），A 谱系在 `codex/v36-freeze-arm` 分支续延（v18
  时代，分支停在 Y_37 之后新增提交、不并入 main）。每谱系一个 X 提交统一登记
  **全部四个新 ID**（两谱系白名单逐字一致，含既有全部已批 ID），随后各身份
  一个仅含本身份清单文件的 Y 提交；`git diff X..Y` 四臂均恰为清单文件一个。
- 登记前复核 v39–v42 未被占用（当前"下一个未批准"pin 测试停在 v39，登记后
  移至 v43）。
- 每身份**恰一次 preflight + 一次 run**，selector 即其段，不触碰回执/subset
  限制。

配对标签 =（块对，场景，repeat_index）。序号映射（DIAGNOSTIC_KERNEL）：
stc_a r1/r2/r3 = 2/41/58；rn_a = 6/45/62；stc_b = 3/44/59；rn_b = 7/48/63；

- 配对：B1↔A1（早 13 对）、A2↔B2（晚 13 对）。目标 12 对（stc_a 6、rn_a 6）、
  不足 9 对、无事件 3 对、锚点 2 对。目标样本与 9-28 轮持平（12 对），机制
  种类从 2 族扩到 4 族；对照从"机制无关"升级为"不足角色 + 无事件角色"。
- 两个目标、三个不足对照、一个无事件对照均在早晚块各至少出现一次；两个

- 墙钟粗估 52×2.2 分钟 ≈ 115 分钟 + 4 次 preflight 与段间核验，预留 4 小时。

  额外付费 0。
- 冻结验收时从四份清单程序化核对上表全部（incident_case_id、

## 4. 回执范围与跨段停止窗口（写实）

- 每身份 preflight 回执与 subset marker 只覆盖本段 selector；跨段无产品级
  状态。产品内滚动窗口只在单段 run 内累计：本轮四段各 13 格均 ≥12，
  **每段都可能触发**（比 9-28 轮的 10 格段更强，但仍是段内防护，不谎称全程）。
- 跨段人工门（仅段间检查）：每段结束后，把已完成各段的模型 backed 终态按
  实际执行顺序合并只取最后 12 格；满 12 格且 ≥10 未通过 → 整个实验停止。
- 整体停止事件（任一发生即停，不启动后续段）：任一段 preflight 失败、
  RUN_SETUP_ERROR、恢复失败（ENVIRONMENT_OR_RECOVERY_FAILURE）、身份/归档
  异常、GATE_INTERNAL_ERROR>0。段间复测 F0 指纹与环境（Docker/子模块/
  porcelain，各段在其 Y 的干净 worktree 内执行）。
- 执行环境配方沿用 v32–v38：隔离 uv 0.11.24、六 DB 键进程注入、模型键
  User scope（不注入 base_url/name）、PYTHONIOENCODING=utf-8、429 规则不变。

## 5. 主次指标与晋级判据（预登记，采用决定轮）

- **主指标**：端到端整格通过（含传输失败格），与 9-28 轮同口径。
- **辅助口径（仅敏感性）**：任一侧格被判定 transport-failed（trace
  `transport_diagnostic=CONNECTION_ERROR|TIMEOUT` 才算；MODEL_ERROR 无该诊断
  不判；metrics requests=0 不代表未发请求）则成对移除后计数。两口径同时
  呈现，禁止混用样本集合比较。
- **完整性前置**：52 格未全部终态、任一配对缺失（transport-failed 对同样
  计入完整性要求，只是不进主分母）→ 不得晋级，结论"不完整/不可判"。
- **不可判条件**：transport-failed 对 > 6（26 对的约 25%）→ 本轮不可判，
  仅报事实。
- **晋级（= 建议在本设计范围内采用 v19）需全部满足**：
  1. 目标组 B−A ≥ +3（分母 12），且 stc_a、rn_a 分别 B ≥ A；
  2. 不足对照组 B ≥ A（分母 9，不放宽）；
  3. 无事件组 B ≥ A（分母 3，不放宽）；
  4. 辅助口径目标组方向一致（B ≥ A）；
  5. 无场景触发反转条件：`Δearly_s ≥ 0 且 Δlate_s < 0 且 (Δearly_s −
     Δlate_s) ≥ 0.5`——两个目标、三个不足对照及无事件对照均检查；锚点
     不检查。触发任一即标记
     "时间顺序嫌疑"并**不晋级**；
  6. 锚点组不进入晋级判定，只与 9-28 同格结果并排呈现作漂移描述。
- 质量晋级条件任一不满足 → 混合/负面结论，**不建议将 v19 作为默认策略，
  不为改判而追加样本**（如需再迭代，回 prompt 开发线重新走 M25 纪律）。
  预检、环境、恢复、身份、归档或传输过多造成的不完整/不可判，则不作
  “质量失败”判定；本方案下不自动补测，后续处理须另行决定。
  结论措辞边界：晋级只意味着"在本设计
  （8 个不同 dev 场景、26 对、BAAB 分块、repeat ≤3）加上 9-28 的 24 对证据范围内
  建议采用 v19"，不构成生产优势或泛化能力证明。
- **机会格执行率（描述性，不进晋级）**：四条件首次机会判定沿用
  9-28 方案 v2 §4 原文（目标关系只从当时公开证据确定；按序扫描首次同时
  满足"已接受目标关系 profile、同关系 schema 未采、schema 工具启用且关系
  在 provable 白名单、无同参调用或拒绝收据"的时点，每 run 最多一次；提前
  满足/预算剔除/run 中断单列）。分母为 0 的（臂×场景）只报计数。本轮对
  目标组与不足组场景均计算——不足组的机会执行情况本身是机制观察。
- **机制观察（描述性）**：两臂各 26 格中已接受 schema 的格数；不足组内
  "错误确认型终态"计数（终态与 TEST_INSUFFICIENT 期望不符的格，逐格列出）；
  预算触顶（8/8）格数；P-1 复核（全 52 格拒绝事件裁决）；早晚块对照计数
  逐场景完整呈现（含样本数）。
- 取舍声明：主指标端到端意味着传输失败计入臂内结果，辅助口径吸收该噪声
  但不动摇主判读；两者矛盾时以主指标为准并如实报告矛盾。

## 6. 分析脚本预登记（9-28 臂对调教训固化为标准件）

- 只读分析脚本在**第二道放行之前**写好并对空归档集干跑自检；脚本必须内置
  臂身份守卫：A 臂（v40/v41）归档 `strategy_prompt_version == p1.kernel.v18`、
  B 臂（v39/v42）`== p1.kernel.v19`，且每格（run_id、case、strategy、
  repeat、sequence）与本方案 §3 selector 表逐项绑定；任何断言失败立即中止、
  不输出任何汇总数。配对组装显式绑定早块 B1↔A1、晚块 A2↔B2，禁止按元组
  次序隐式解包。
- 脚本只读：不修改任何归档产物，不重跑模型；修正分析逻辑只允许重算，原始
  产物一律不动。
