# Kernel v19 确认性测量方案（设计稿，2026-09-28，待批准）

状态：设计稿。机制复盘（`2026-09-28-v33v34-mechanism-review.md`）未发现需要
修复的产品机制，按 owner 指令提出本方案；不授权执行。暂不改 prompt。

## 1. 要回答的问题

在排除执行顺序时间混杂、并把 provider 传输失败从策略分母中预登记排除后，
v19 的目标改善是否在更大样本上复现，且对照组不退化？

## 2. 设计要点

- **身份**：新建 `p1-formal-v35`（v18 对照）/ `p1-formal-v36`（v19 候选），
  构造配方与 v33/v34 完全相同（登记双 ID → X → freeze → Y → 检出门）；
  不复用 v33/v34（其 suite 已有 subset/回执状态，避免追加解释负担）。
- **规模**：目标两场景每臂 **8 次**（16 对，主分母）；对照四场景每臂 3 次
  （12 对，监视分母）；每臂 28 格，两臂 56 格，逻辑请求上限 56×8=448。
- **执行顺序（控制时间混杂）**：**ABBA 交错**——B 前半（目标 4+对照一半）→
  A 前半（同结构）→ A 后半 → B 后半；四段 selector 在冻结验收时一次性登记，
  执行期不得改段。两段之间复测 F0 与环境。这把单调时间漂移从"臂间差异"转为
  "段间差异"，可在分析中按段检验。
- **传输失败预登记口径**：终态 MODEL_ERROR 且 trace 带
  `transport=CONNECTION_ERROR|TIMEOUT`（或 req=0 的协议中断）的格记为
  **transport-excluded**：不计入策略分母、单列报告；分母缩减如实呈现，不补跑。
  该口径在本方案冻结时固定，不得看结果后调整。
- **停止**：滚动窗口与失败即停按现有合同；任一段 preflight 失败/身份异常/
  GATE_INTERNAL_ERROR>0 → 实验停止。每段一次 preflight/run，无重试。
- **预算**：现有套餐内、额外付费 0；墙钟粗估 56 格 ≈ 2×36 格 ≈ 2 小时级别，
  预留 3 小时。

## 3. 分析与预登记规则

- 主指标不变（整格通过，transport-excluded 不进分母）；目标 16 对为主判据，
  对照 12 对为退化监视。
- 晋级条件（预登记）：目标组 B−A ≥ 3（分母按实际非排除格、双方均 ≥6）且
  duplicate_a/orphan_a 分别不降；对照组 B ≥ A−1 且无错误确认增加；B 的
  schema 执行率（机会格中采核比例）≥ A+0.3。
- 段间一致性检查：若任一场景的通过在"先跑段"与"后跑段"方向性相反且差 ≥2，
  报告时间漂移嫌疑，不晋级。
- 交付：逐格表、四格表、传输排除清单、执行率、P-1 复核、规则逐项判定。

## 4. 边界

不动 prompt、不改评分/控制器/预算；dev 场景、筛选性质、不宣称泛化；两道
放行（冻结 / 执行）沿用本次惯例，执行需另批。
