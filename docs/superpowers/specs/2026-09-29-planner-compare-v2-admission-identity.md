# T12 实验 v2 准入身份绑定（2026-09-29）

状态：第一道放行的实施合同；不放行真实模型 preflight 或测量。`p1-planner-compare-v1` 清单、归档和检出修订保持原样。

## 目标

`v1` 已冻结场景摘要，但没有冻结 T06 准入身份。旧的正式 12 场景证书缺必填合同摘要，不能迁移为当前证书。`v2` 只在当前合同的 12/12 认证与准入成功后冻结；场景、策略、模型配对、预算、赛程和评价合同沿用 `v1`，不得用准入整改顺带改变测量条件。

## 证据与公开边界

管理平面使用一次 `certify --admit` 产生的 `ScenarioAdmissionReport`，原件保存在忽略的 `artifacts/admissions/`。它含私有卡片和认证详情，不进入 Git 或模型上下文。报告必须按正式赛程顺序恰有 12 个唯一场景；每项 `admitted=True`、`reasons=()`、`certification.certified=True`，准入、证书及当前 `ScenarioSpec.digest()` 三个合同摘要相等，case ID 一致，卡片完整、对称性核对通过，且当前 `scenario-sets.json` 将其登记为 dev。生成器须用当前合同与原证书重新执行 `build_admission` 并与原件逐项核对，而非只相信原件中的布尔值；任一项不成立即拒绝生成身份材料。

从经严格加载的原件生成一份可入库的脱敏证明，固定格式 `p1.planner_admission_attestation.v1`：整份原始报告的文件 SHA-256，以及按正式场景顺序排列的 `(case_id, scenario_digest, admission_entry_sha256)`。每条摘要由已校验 `ScenarioAdmission.model_dump(mode="json")` 的规范 JSON 计算。证明不得含卡片正文、根因、期望答案、工具轨迹、路径中的密钥或其他私有字段。生成器写一次并拒绝覆盖；原件及生成命令、摘要记入冻结报告，供持有管理平面原件的审计者复核。

## 清单与验证

`p1-planner-compare-v2` 使用显式的新清单 schema/身份，绑定脱敏证明的规范摘要。加载器要求 v2 的准入身份非空、结构有效，且正式 12 场景顺序和摘要与清单 catalog 一致；v1 不允许携带该字段。`experiment verify` 在全新干净检出中重读已入库证明，核对其摘要、12 个场景与当前合同及 dev 登记；运行时的清单确认、doctor、规划器探针及正式报告沿用同一身份核对。仅有证明而没有通过原件验证的构建路径不得冻结 v2。

冻结顺序为：完成一次认证准入并保留原件 → 生成并审计脱敏证明 → 将代码、证明与本合同提交为绑定修订 X → 官方命令生成清单 → 仅提交清单为 Y → 在 Y 的独立干净工作树验证 v1/v2、证明绑定、108 格赛程与真实检出门。X→Y 若出现清单以外路径即失败。第二道真实执行仍需单独放行。
